How to attack any DFA question

🧭 The 5-step method
  1. Write 3 accepted and 3 rejected strings first — include the shortest accepted one and an overlapping one.
  2. Find the type (count? length? substring? start/contains/end?). The type tells you the shape.
  3. Ask “what must I remember?” Each different thing to remember = one state. Name states by meaning (“seen ba”, “odd a’s”).
  4. Give every state an edge for every symbol. Missing edges → dead state. Use the box method for failed matches.
  5. Test your strings by walking through the diagram, then write the 5-tuple / transition table if asked.
⚠ Where marks are lost
  • Missing transitions (a DFA must be complete — one edge per symbol from every state).
  • No start arrow, or accept states not double-circled.
  • Going back to the start on a mismatch when part of the pattern already matches (e.g. 1010 while looking for 1011 → go to “10”, not q0).
  • Ignoring overlaps between “starts with”, “contains” and “ends with”.
  • Wrong ε handling: is the empty string accepted? (Zero is even and divisible by everything.)
  • Reading Σ carelessly — extra symbols (like c, 2, w) still need edges.
▶ Using the visualiser
Open any question, type a string (or click a sample chip) and press Run or Step ▶. The current state is highlighted in yellow, the edge just taken lights up, and the matching cell of the transition table is marked. At the end the final state turns green (accepted) or red (rejected). Hover over a row in “What each state means” to find that state in the diagram. Use 🎯 Quiz me to practise.
