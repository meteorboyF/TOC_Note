Basic Concepts

Everything you need before designing automata: the vocabulary (Σ, strings, languages), the formal definition of a DFA and how it processes input. Try the small tools on this page as you read.

1 · Model of computation

A model of computation is an assumption about how a machine behaves: for certain inputs we get certain outputs. It is an abstract representation of a physical machine. We ignore the hardware and keep only what matters: what the machine can remember and how it reacts to each input.

The simplest model is the finite automaton: a machine with a finite amount of memory (its states). Real examples: a light switch (ON/OFF), an automatic door controller, a vending machine, the lexer in a compiler.

2 · Symbol, alphabet, string

Symbol — the basic building block of a system; any character or token. Examples: a, b, 0, 1, +, @, int.
Alphabet (Σ) — a finite, non-empty set of symbols. ΣEng = {a, b, …, z}, Σnum = {0, 1, …, 9}, Σbin = {0, 1}.
String (word) — a finite sequence of symbols over an alphabet. Over Σ = {a, b}: abba, b, aaab.
Empty string (ε) — the string of length zero. |ε| = 0. Note that ε is a string, not a symbol, and ε ∉ Σ.

Useful definitions

  • Length |w| = number of symbols. |abba| = 4.
  • Concatenation xy = x followed by y. If x = ab, y = ba then xy = abba. wε = εw = w.
  • Reverse wᴿ: abb → bba. A palindrome satisfies w = wᴿ.
  • Prefix of w: any start part (including ε and w). Suffix: any end part.
  • Substring: any consecutive part. “bac” is a substring of “abaca”, but “bc” is not.
💡 Why this matters for DFAs
“Starts with X” is a prefix condition, “ends with Z” a suffix condition, and “contains Y” a substring condition. Matching a pattern means tracking the longest suffix of what you read that is a prefix of the pattern; that idea solves most DFA questions.

3 · Powers of an alphabet: Σⁿ, Σ*, Σ⁺

  • Σⁿ = the set of all strings of length exactly n. |Σⁿ| = |Σ|ⁿ.
  • Σ⁰ = {ε}: exactly one string of length 0.
  • Σ* = Σ⁰ ∪ Σ¹ ∪ Σ² ∪ …: all strings, including ε (Kleene star). Infinite, but every string in it is finite.
  • Σ⁺ = Σ¹ ∪ Σ² ∪ … = Σ* − {ε}: all non-empty strings.

4 · Languages & operations

Language — any set of strings over Σ, i.e. any subset L ⊆ Σ*. It can be finite ({ab, ba}), infinite ({w | w has even length}), or empty (∅). Note that ∅ ≠ {ε}.
  • Union L₁ ∪ L₂, intersection L₁ ∩ L₂, complement L̄ = Σ* − L.
  • Concatenation L₁L₂ = { xy | x ∈ L₁, y ∈ L₂ }.
  • Power L⁰ = {ε}, Lⁿ = L·Lⁿ⁻¹. For example L² = LL. Kleene star L* = L⁰ ∪ L¹ ∪ L² ∪ …

5 · Finite automata

A finite automaton reads the input one symbol at a time, left to right. It has finitely many states, which are its only memory. After the last symbol, if the machine is in an accept state, the string is accepted; otherwise it is rejected.

Parts of a state diagram

  • States: circles (q0, q1, …).
  • Start state: the one with an arrow coming from nowhere.
  • Accept states: double circles.
  • Transitions: arrows labelled with symbols.
  • Dead (trap) state: a non-accepting state that loops on every symbol. Once you enter it, the string is rejected.

6 · Formal definition: the 5-tuple

A deterministic finite automaton is a 5-tuple M = (Q, Σ, δ, q₀, F) where

  1. Q is a finite set of states,
  2. Σ is a finite set called the alphabet,
  3. δ : Q × Σ → Q is the transition function (one next state for each state–symbol pair),
  4. q₀ ∈ Q is the start state,
  5. F ⊆ Q is the set of accept states.

7 · How a DFA computes

Let M = (Q, Σ, δ, q₀, F) and w = w₁w₂…wₙ. M accepts w if there is a sequence of states r₀, r₁, …, rₙ such that

  1. r₀ = q₀ (start in the start state),
  2. δ(rᵢ, wᵢ₊₁) = rᵢ₊₁ for i = 0, …, n−1 (follow the transitions),
  3. rₙ ∈ F (end in an accept state).

The extended transition function δ̂ runs a whole string: δ̂(q, ε) = q and δ̂(q, wa) = δ(δ̂(q, w), a). Then w is accepted ⇔ δ̂(q₀, w) ∈ F. The “δ̂ trace” line under every visualiser is exactly this sequence r₀ → r₁ → … → rₙ.

L(M), the language of M, is the set of all strings M accepts. We say M recognises L(M).

8 · Regular languages

A language is regular if some finite automaton recognises it. Every language in the DFA section is regular. Not everything is: {aⁿbⁿ | n ≥ 0} needs unbounded memory to compare the counts, so no DFA exists for it. (Compare it with aⁱbʲ, where i and j are independent: that one is regular.)

9 · Designing a DFA: “be the automaton”

The key question from the slides: what do I need to remember about the string so far? Each distinct situation becomes a state.

  • Odd number of y’s → remember “even so far” or “odd so far” → 2 states.
  • Contains 001 → remember how much of 001 has been seen: nothing, “0”, “00”, or all of “001” → 4 states.
  • Length divisible by 3 → remember length mod 3 → 3 states.
Dead state & completeness
A DFA must have exactly one transition for every (state, symbol). If a situation can never lead to acceptance (“started with the wrong symbol”), send it to a dead state that loops on every symbol.
Complement
For “does NOT …” languages, build the DFA for “…” and swap accept and non-accept states. The DFA must be complete first, dead state included.
Product (AND / OR)
Two conditions → run both DFAs at once: states are pairs (p, q). AND accepts when both parts accept; OR accepts when either part does.
Test before you finish
Always walk the shortest accepted string, a tricky overlapping string, and ε through your diagram.

10 · Writing the answer in the exam

  1. Language understanding: write 2–3 accepted and rejected strings (shows the examiner you read it right).
  2. State diagram: start arrow, double circles for accept states, every state has one edge per symbol, dead state drawn.
  3. State meanings (optional but valuable): a short note under each state, e.g. “q3: seen ba”.
  4. If asked for components / 5-tuple: Q = {…}, Σ = {…}, δ as a transition table (mark → start and * accept), q₀, F = {…}.
